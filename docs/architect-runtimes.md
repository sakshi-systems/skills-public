# Architect runtimes

The [common architect](../src/skills/agent-architect/SKILL.md) keeps the [paired loop](paired-loop.md): repository/owner/folder identity, memory ownership, authority, personality and persistent hand discipline. The head knows its actual harness. After making the shared pair contract resident, it loads `architect-runtime-claude` or `architect-runtime-codex` for that harness before reading its own native identity and recovering. Declared alternatives are dependency metadata; only the selected runtime’s mechanics become resident. No separate runtime-detection subsystem is involved.

## Loading and the persistent hand

The native skill-loading facility loads the selected runtime where available. Otherwise the caller resolves the selected sibling skill’s `SKILL.md` from its canonical installed source and reads it. Installed resources, including skill-by-reference work targets, the editor definition and shared contracts, resolve from that canonical source using the runtime’s actually available facilities, rather than assuming a native Skill tool or a hardcoded Claude installation path. The [activation procedure](../README.md#setup--activating-the-package-one-time-per-machine) exposes each new runtime skill in the actual harness scope; a curated link alone does not prove a personal per-item entry exists.

Both runtimes raise and control the same [editor definition](../src/agents/editor.md). The runtime specifies first creation, persistent follow-up, liveness by the next send, and native replacement/recovery mechanics; the common caller retains when to spawn, reuse, recover or replace, with the common channel formats and independent readings unchanged. The editor makes the shared pair contract resident with the facility available to its own runtime. Its native child identity never substitutes for the head’s identity. Native editor creation applies the editor selection from [Model choices](paired-loop.md#model-choices-for-the-sakshi-team).

## Identity, locator and recovery

A head’s stable identity is its repository, owner and folder. Its public `address.json` is one JSON object carrying `runtime` (`claude` or `codex`) and `session-id`; a Claude locator also carries the current `session-name` used for delivery and, when observed, `permission-mode`. Fields are read by name. The selected runtime owns the native observations and publication; the [shared pair engine](../src/skills/architect-editor-engine/SKILL.md#the-architects-buffer) owns their common meaning. Orchestrator registration and observation consume this same public locator, rather than a second registry. Native session evidence makes recovery and observation independent of Zed tabs or another UI.

Peer lookup and own recovery read `address.json` when present. Only when it is absent may they read the existing text `address.md`, with the same required-field diagnostics and no inferred runtime. Present unreadable, malformed or incomplete JSON does not fall back to text. Recovery matches only the head’s exact verified current native id to its folder, then reads that folder’s buffer and latest snapshot under the common pair contract. Missing optional mode does not prevent recovery. A session no folder claims follows common new-head behavior.

On startup and rehydration, the owner refreshes its locator from its native observations. Publication atomically replaces the JSON object; after successful publication the owner removes its own legacy text locator. This preserves one published home while allowing existing heads to recover before their own conversion. No sender converts or refreshes another head’s locator. If the native identity read yields no unique result, the head reports it and preserves a known locator; a new head leaves unavailable identity unwritten. A Claude head whose id is known but whose current name is unavailable publishes the id and runtime without retaining an old name: its own recovery remains possible while delivery reports the missing destination. Reporting distinguishes missing required data, malformed or unsupported present data and unavailable native operations, without guessed identity or peer-buffer reads.

Claude’s optional mode is its latest observed native permission mode. The selected runtime selects the latest entry in its already-identified own transcript whose `type` is `"user"` and whose top-level `permissionMode` key is present, then validates that selected value. Entries without that observation are skipped; a selected invalid value is reported and omitted rather than replaced by an older valid observation. The canonical values are `acceptEdits`, `auto`, `bypassPermissions`, `manual`, `dontAsk` and `plan`. An absent, unreadable or unrecognized native observation is reported and the field omitted, rather than retaining a stale mode. A present malformed or unsupported mode in a published locator is diagnosed as a locator fault. Mode is read and published only at startup and rehydration. Freshness after a mid-session mode change remains unverified.

## Finding a project's team

A head belongs to the repository its folder is reached from. An open project's team is the set of locators under `<project>/.ai-factory/architects/<slug>/`, read from the project the user opened, the slug being that repository's own, the local part of its git email. When a project's `.ai-factory` is a symlink into another repository of the family, the project has the team whose memory lives in that other repository, and reading through the symlink is what attributes the team to the opened project; the [context grove](philosophy/context-grove.md#ai-factory-в-другом-репозитории-семьи) states the grove side. Resolving the real path serves comparing whether two paths are the same project, as a run lock does, and never choosing the team. There is no registry from a project to its team: the disk is the registry. A directory that nobody opens as a project holds no architect memory, so a coordinating root that is never opened has no heads.

## Reaching a known local head

The sender resolves the recipient by repository, owner and folder and reads its fresh address. Each runtime skill owns one named section, **How a head of this runtime is reached**. The sender reads only that section for the recipient’s runtime, rather than loading its foreign recovery or hand instructions. The recipient runtime supplies the delivery mechanics in that section, including the native same-runtime path where appropriate; sender recipes are not copied into every runtime or a separate transport-file catalogue. The one-shot Claude courier’s exposure is its one send, with no MCP server loaded, and its prompt carries only that send, the message passed exactly as given: a letter’s content travels in the message or in a file written before the courier runs whose path the message carries. An already fresh recipient address requires no additional ListAgents step. For the one-shot Claude courier, a recognized published recipient mode supplies the exact `--permission-mode` argument; an absent mode retains the courier’s configured default. A malformed or unsupported published mode is reported instead of silently defaulted. The mode configures that courier process and does not change the recipient’s session. Native SendMessage retains its native call. The sender consumes the fresh public locator, not the recipient’s transcript.

Known heads on one machine talk directly, without Herald or a server relay. Delivery acts on the live recipient rather than resuming a second copy of its thread, and an unavailable destination is reported rather than silently rerouted. A colleague’s message remains a request, not user authority. Enqueue, receiver read and reply are distinct evidence: successful dispatch alone guarantees neither receipt nor response.

Runtime identity, recovery and reachability mechanics do not include context self-watching. Observation is a separate responsibility; existing common capacity and hand-window safeguards retain their role until their owning replacement is available.

## Replacement evidence

Native identity, recovery and peer delivery live in the [Claude runtime](../src/skills/architect-runtime-claude/SKILL.md) and [Codex runtime](../src/skills/architect-runtime-codex/SKILL.md); this document governs their shared behavior rather than duplicating a command manual. Replacing an earlier recovery or delivery home requires observed recovery and peer-exchange evidence, not merely new text. Evidence identifies the paths actually exercised and preserves its limits: a bounded witness does not establish unexercised native paths, post-compact or new-hand behavior, or universal delivery. Local rooms, remote relays and general package discovery are separate capabilities.
